Phase 4 accepted risk posture: the verification implementation is complete for the controlled synthetic/demo path. General live verification, confidential data, and ordinary-user provider access remain disabled pending a separate rollout decision.

- **R-21 — Workflow completion may be over-read as source or legal acceptance.** Mitigation: separate axes in schema/API/UI, immutable Phase 4 links, prohibited-language scan, human-review-pending labels. Residual: user training remains necessary.
- **R-22 — A human may link the wrong same-workspace PDF artifact.** Mitigation: private parsed-document allowlist, explicit review states, audit link history, no automatic truth inference. Residual: content-level artifact review is human work.
- **R-23 — Phase 4 human-review changes create a new generation input.** Mitigation: stable-key regeneration, preserved human fields, obsolete-not-delete behavior, audit history. Residual: complex corrections may require reviewer reconciliation.
- **R-24 — Coarse owner/reviewer roles are insufficient for a production waiver authority matrix.** Mitigation: same-workspace validation plus append-only decisions in demo; unrestricted rollout remains blocked pending policy design.
- **R-25 — Dependency advisory drift.** The root now pins compatible Next `16.2.12`, PostCSS `8.5.19`, and Sharp `0.35.3`; the current lockfile audit reports zero vulnerabilities. Residual: upstream advisories can reappear, so dependency audit remains a required release gate.
- **R-26 — Deterministic proposal matching may miss unusual valid prose.** Precision-first matching renders missing/partial states for human review instead of guessing. Expand synthetic/public fixtures before broader use.
- **R-27 — A draft assertion may be mistaken for company proof.** `proposal-support-policy-v1` prohibits self-support; reviewed same-workspace evidence or human proof is required.
- **R-28 — Proposal tables/images may parse poorly.** Parser uncertainty fails closed and links to the original page. OCR/table recovery remains a residual limitation.
- **R-29 — Copied procurement language may survive when identity is implicit.** Explicit customer/RFP identity mismatches are critical; paraphrased or identity-free copied prose remains a human-review risk.
- **R-30 — A copied signed export URL is a bearer credential until expiry.** Five-minute expiry, workspace authorization before grant creation, private storage, no URL persistence, revocation, and audit reduce exposure. Immediate recall still depends on backing-object deletion propagation.
- **R-31 — Structured HTML is not a pixel-stable PDF.** Phase 7 deliberately uses escaped self-contained HTML because the repository has no compatible safe PDF generator. Browser/print rendering can vary; add a reviewed generator only under a later format decision.
- **R-32 — Snapshot reports can become stale after a human decision.** Source snapshot time, input hash, run IDs, review denominators, and generation history are visible. Users must generate a new immutable snapshot to include later decisions; old snapshots remain audit records.
- **R-33 — Spreadsheet applications have evolving formula heuristics.** All cells with leading `=`, `+`, `-`, or `@` after whitespace are neutralized and fixture-tested. Maintain the policy and regression corpus as spreadsheet behavior changes.
- **R-34 — Retention cleanup requires the server-maintenance path to run.** Objects deny grants after `retention_until`; `purgeExpiredReportExportsForMaintenance` removes them and preserves audit history. Deployment scheduling remains an operational rollout task.
- **R-35 — Complex tables exceed deterministic inference.** Preserve cells/geometry/warnings and require review; pixel-perfect arbitrary reconstruction is not claimed.
- **R-36 — DOCX/XLSX rendered pagination is unstable.** Use paragraph/sheet/cell provenance and never invent PDF page coordinates.
- **R-37 — XLSX cached formula values may be stale.** Store formulas and cached values separately with a warning.
- **R-38 — Selective OCR may miss unusual damage.** Fail closed as parser uncertain; production OCR requires separate approval.
- **R-39 — Archive traversal/expansion attack.** Enforce strict names, entry/count/ratio/expanded-size limits, approved types, and no nesting.
- **R-40 — Cost estimates differ from invoices.** Version pricing, persist ranges/hard maximum, and keep paid paths reservation-gated.
- **R-41 — New addenda stale downstream analysis.** Targeted dependency invalidation preserves unchanged normalization and invalidates downstream cache.
- **R-42 — Office documents expose printed page labels that differ from rendered pages.** Phase 9 accepts only rendered-page exact/normalized-exact evidence and records native DOCX section or XLSX sheet/cell provenance. The provider-free correction re-anchors a candidate only when its own quote has one unique rendered-page match; it recovered five bindings. A quotation occurring on both pages 24 and 34 remains ambiguous rather than being silently rebased.
- **R-43 — A public fixture may not naturally contain every adversarial control case.** FAC115 contains no genuine unresolved amendment conflict, planted parser-uncertain obligation, or malicious prompt injection. The preflight records the coverage gap instead of modifying official source bytes. A separately labeled synthetic companion requires an explicit evaluation-design decision.
- **R-44 — Historical extraction recall can make verification metrics misleading.** Phase 9 maps frozen answers to the exact accepted population before calls. After safe rendered-page recovery, 13/23 bind and ten remain missing or ambiguous; a completed verification run cannot hide these extraction gaps.
- **R-45 — Public evaluation spend can consume unrelated phase headroom.** The Stage 0 reader paginates the full ledger, reports phase/public/cumulative totals separately, and reserves the entire planned stage before provider construction. A dedicated Phase 9/public ceiling and explicit call authorization remain required.
- **R-46 — High-recall deterministic mining can over-generate.** Discovery and support are separate; exact duplicates are removed, only bounded uncertain families receive paid verification, and remaining weak candidates stay unverified/human-reviewable. Residual: candidate-volume usability needs broader public-document testing.
- **R-47 — Token estimation differs from provider billing.** The hard plan uses conservative serialized-input and task-output limits; a separate forecast is compared to actual usage, and per-call usage above its plan fails closed. Residual: provider tokenizer/pricing changes require a new pricing version.
- **R-48 — Cache reuse can preserve stale semantics.** Cache identity includes every source/parser/prompt/schema/model/evaluator input and accepts only complete schema-adherent hash-valid results. Residual: an omitted future semantic input would require a cache-version bump.
- **R-49 — Public FAC115 success may not generalize.** Separate holdouts cover native, 100+ page, table, spreadsheet, addendum, and scanned shapes; adversarial cases stay separate. Residual: unrestricted rollout requires more public-domain qualifications and reviewer operations.
- **R-50 — Repeated exact quotations can create false page precision.** Same-document locations remain linked with `evidence_location_ambiguous`; no arbitrary page is selected. Residual: some cases require human structural review.
- **R-51 — Jurisdiction-neutral support may be mistaken for universal accuracy.** The planner and worker no longer depend on a state-specific fixture, but extraction quality still varies with source layout, scans, tables, amendments, and procurement vocabulary. Mitigation: exact document bindings, bounded contexts, strict schemas, machine-only findings, and human review. Residual: qualify additional public holdouts before unrestricted rollout.
- **R-52 — Provider account quota can stop an otherwise valid run.** Reservations protect the application ledger but cannot create provider credit. Quota exhaustion is normalized, releases the reservation, produces no findings, and is not retried automatically. Residual: operations must monitor provider billing/quota separately before enabling an authorized run.
- **R-53 — High-recall public mining can overwhelm reviewers with technically quoted but non-actionable text.** The general-workspace refinement rejects navigation, descriptive, incomplete, and non-obligatory candidates and applies material category rules before findings. The later immutable corrected New Jersey run contains 329 findings; review acceleration orders all of them but does not exclude any. Residual: there is no independently approved known-answer precision/recall score, so human review and additional public holdouts remain required before unrestricted use.
- **R-54 — Review acceleration may be mistaken for automatic acceptance.** The UI can reduce interactions, but every batch is still an explicit human confirmation and creates one append-only decision per finding. Critical and exception lanes are individual-only; the server recomputes all eligibility and rolls back a stale/mixed batch. Residual: onboarding and operating procedures must continue to reinforce that the proposal team owns each decision.
- **R-55 — Deterministic duplicate rules may miss true semantic duplicates.** Exact signatures deliberately favor false-merge prevention over maximum grouping. Every occurrence remains visible and may still require individual review. Residual: reviewers can see related source occurrences, but no model/fuzzy grouping is introduced in this release.
- **R-56 — A lower interaction estimate may be read as a guaranteed time saving.** The estimate is a documented range based on conservative defaults and only sufficiently sampled timing observations. It excludes no finding or page exception and is labeled approximate. Residual: validate the range with privacy-preserving real reviewer sessions before using it for ROI commitments.
- **R-57 — Review prioritization may be confused with extraction completeness.** Lanes order the machine population; they cannot reveal an obligation that extraction never proposed. Page coverage, parser uncertainty, unassessed signals, and the draft source-only benchmark remain separate controls. Residual: the New Jersey evaluation has no independently approved known-answer precision/recall score and cannot support a complete-recall claim.
- **R-58 — Interaction telemetry can drift toward sensitive-content capture.** The schema allowlists identifiers, event types, timestamps, versions, and bounded non-sensitive metadata; document text, quotations, proposal content, prompts, tokens, and secrets are prohibited. Analytics has no authorization or publication effect. Residual: review metadata additions require privacy/security review.
- **R-59 — Guided-tour drift can hide a broken demo or obstruct the real interface.** Semantic targets, route-aware target waiting, optional fallbacks, and a required-target readiness gate replace pixel coordinates and silent skipping. The tour is exit-able and not a workflow dependency. Residual: any route/target change must update the versioned definition and readiness fixture together.
- **R-60 — A polished tour may overstate product certainty.** Tour copy explicitly separates machine findings, human decisions, publication, checklist work, and company proof; it forbids completeness/compliance/submission-safety claims and never performs protected actions. Residual: presenter coaching still matters, especially when discussing arbitrary public RFPs.
- **R-62 — A dashboard projection could disagree with authoritative review/publishing state.** The read model now counts invalid accepted decisions and immutable findings not represented in the review queue, and it treats either condition as publication-blocking. Residual: every new review or publication projection must reuse authoritative predicates and receive regression coverage.
- **R-63 — Latest-run convenience can blur historical provenance.** The operating register is explicitly scoped to the latest completed verification scope, while historical runs remain immutable/auditable. Prepared demo checklist, audit, and report views bind an exact completed generation run. Residual: any future cross-run comparison must be an explicit, labelled audit feature rather than a default UI join.
