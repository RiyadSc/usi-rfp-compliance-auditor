# Risk Register

Last updated: 2026-07-18 after Phase 4 closure.

| ID  | Risk                                                             | Current control                                                                                                                            | Residual / next decision                                                                                   |
| --- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| R1  | Model fabricates or overstates a requirement                     | Candidate-centered entailment plus adversarial challenge; exact quote/page validation; deterministic decision engine; human review pending | Frozen-fixture performance does not prove all future documents; unrestricted live rollout remains disabled |
| R2  | Addendum ordering produces a false active requirement            | Explicit amendment verbs and referenced scope drive precedence; unresolved authoritative values become `conflicting`/`undetermined`        | Procurement-specific ordering rules may need new deterministic adapters                                    |
| R3  | Parser damage is mistaken for absence                            | `parser_uncertain` is fail-closed and cannot become supported                                                                              | OCR/image/table recovery is still limited in the demo                                                      |
| R4  | Similar requirements are destructively merged                    | Deterministic pair generation, typed material-scope hard blocks, relationship proposals only                                               | Human review remains required for semantic duplicate proposals                                             |
| R5  | Prompt injection changes application behavior                    | Hostile-content delimiters, no tools/secrets, strict schemas, deterministic injection rules, frozen attack fixtures                        | New injection forms remain possible; keep fixtures and provider monitoring current                         |
| R6  | Cross-workspace data leakage                                     | RLS, composite scope FKs/triggers, workspace-filtered retrieval, authorization and browser denial tests                                    | Any new Phase 5 query must carry the same workspace/run scope                                              |
| R7  | Incomplete model/run provenance                                  | Immutable scope hashes, fingerprint assertion, required run input hash, persisted pass/call metadata                                       | Any configuration change invalidates compatibility and requires requalification                            |
| R8  | Provider retention or policy is unsuitable for confidential data | Synthetic/public-only usage; `store:false`; no full prompt artifact                                                                        | Contractual ZDR and production data governance are unverified; confidential use remains prohibited         |
| R9  | Cost or retry runaway                                            | Separate phase ledgers, pre-call ceiling reservation, per-call ledger rows, bounded retries/timeouts                                       | Phase 5 paid use needs its own authorization and ceiling                                                   |
| R10 | Automation bias / premature approval                             | Separate support, precedence, proof, and human-review axes; machine-only/pending UI; no compliance/readiness claim                         | Reviewer training and rollout policy remain required                                                       |

Phase 4 accepted risk posture: the verification implementation is complete for the controlled synthetic/demo path. General live verification, confidential data, and ordinary-user provider access remain disabled pending a separate rollout decision.
