# Phase 8 Hardening Data Flow

```text
immutable Phase 4–7 synthetic records
  -> exact Phase 8 binding + canonical hashes
  -> validated completed-analysis cache
  -> protected prepared-demo views
  -> private, labeled Phase 7 fallback (optional)
  -> short-lived authorized grant
```

Sensitive mutations first authenticate and authorize the exact workspace, then consume a fixed server-owned rate bucket. Any provider-capable operation additionally validates rollout flags, scope/fingerprint/provenance, and atomically reserves the maximum projected budget before provider construction. Phase 8 does not call a provider.

Performance events contain only bounded operational metadata. Reset validates the exact synthetic scope/cache hash, changes only presentation state in one transaction, and appends reset/audit rows. Immutable upstream records and ledgers are never reset.
